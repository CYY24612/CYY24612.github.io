上一篇文章讲了 PCIe 的分层架构。这一层——数据链路层(Data Link Layer, DLL)——是整个 PCIe 可靠性设计的核心:它的任务是在一条**物理上不可靠**的链路上,建立一个**逻辑上绝对可靠**的数据通路。

## 三个职责

数据链路层要做三件事:

1. **保证数据完整性**:给每个 TLP 包"穿上防弹衣",任何一点比特损坏都能立刻发现;
2. **错误校正**:包丢失或损坏时自动安排重发,整个过程上层软件完全不知道,不需要干预;
3. **链路管理**:处理日常"沟通"工作,比如流量控制(Flow Control)和电源状态管理(PM)。

前两条是这篇文章的主角,第三条我们最后简单带过。

## 发送端:给 TLP 穿上防弹衣

数据链路层拿到事务层的 TLP 后,做三步处理:

```
第一步:分配序列号
    给数据包一个独一无二的身份 ID —— 插入一个 12bit 序列号

第二步:附加校验码
    给数据包贴上"防伪封条" —— 追加 32bit 的 LCRC 校验码

第三步:存入备份
    把包副本放进重传缓冲区(replay buffer),没确认前不删除
```

### 序列号:数据包的临时身份证

12bit 的序列号,取值范围 0-4095,由发送端的 **NTS(Next Transmit Sequence)计数器** 管理,按发送顺序递增赋给每个 TLP。

它的作用在接收端体现:接收端维护一个 **NRS(Next Receive Sequence)计数器**,记录"我期望收到的下一个序列号"。两个计数器的值能对上号,通信才能继续。

> 序列号不是用来防止"偷听"的安全机制,它只做两件事:**检测丢包** 和 **检测乱序**。

### LCRC:32 位的数字指纹

LCRC(Link CRC)是 32bit 的校验码,发送端根据包内**所有数据内容**算出来,用于**点对点**校验。

为什么叫"点对点"?因为 CRC 只在**相邻两个端口之间**计算和校验——下一跳的接收端验完就重新算新的。每个链路段的 LCRC 都是独立计算的,这保证哪怕经过交换机中转,每一段传输的错误都能在本地被发现。

任何 1bit 错误都会导致 LCRC 不匹配,接收端当场就能发现。

### 重传缓冲区:包的安全备份

发送端把发出去的每一个 TLP 的副本都存进重传缓冲区,**在没有收到明确的 Ack 之前,这个副本不会删除**。

这是可靠传输的基石:物理链路可能丢包,但只要发送端手里有副本,丢了我就能重发。用空间(缓冲)换可靠性,用协议的简单换取硬件的确定性。

## 接收端:三道安全检查

接收端收到一个包,按顺序检查:

```
第一步:检查 LCRC
    包在传输过程中是否损坏?

第二步:检查序列号
    它是不是我期望的那一个?有没有乱序或丢包?

第三步:做出决定
    接受 / 丢弃 / 请求重传
```

LCRC 不过 → 包已损坏,直接丢弃并触发重传机制;序列号对不上 → 可能是乱序,也可能是前面的包丢了,同样进入重传流程。

## 确认与重传:Ack / Nak 协议

接收端通过 DLLP 向发送端反馈。DLLP(Data Link Layer Packet)是**只在直连的两个端口之间**使用的短小管理包,从不经过交换机路由——它只传递管理和状态信息,不会把数据带到链路之外。

| DLLP 大类 | 关键包 | 作用 |
| --- | --- | --- |
| Ack/Nak | Ack、Nak | 可靠性与错误校正 |
| 流控(FC) | InitFC、UpdateFC | 管理缓冲区空间 |
| 电源管理(PM) | PM_Enter_L1 | 管理低功耗状态 |

两个最重要的语义:

- **Ack**:接收端告诉发送端——"你发的**某个序列号的包,以及它之前所有的包**,我都安全收到了,没问题,你可以把备份删除了"。这是**累计确认**,一次 Ack 可以释放重传缓冲区里的一串包。
- **Nak**:紧急信号——"出问题了,我最后一个收到的好包是**这个序列号**,它之后的数据肯定有问题,请重发"。

发送端收到 Nak(或重传定时器超时),就把重传缓冲区里对应序列号之后的包重新发一遍。这个重发过程**完全在硬件里完成**,事务层、驱动、应用都感知不到链路上曾经丢过包——这就是"可靠传输对软件透明"的含义。

## 流量控制:避免缓冲区溢出

流控(Flow Control)解决另一个问题:发送端不能无节制地发,接收端缓冲区装不下会丢。

- **InitFC**:链路初始化时,双方互报"我的缓冲区能装多少"——接收缓冲区信用值(credit);
- **UpdateFC**:接收端每消化掉一些数据,就发 UpdateFC 告诉发送端"我又腾出空间了"。

发送端手里始终掌握着接收端的"信用额度",发出的数据总量不会超过对方缓冲区的容量。这个机制和网络 TCP 的滑动窗口思路同源。

## 小结

数据链路层的设计,值得记住的是这几个点:

1. **三层保护**:序列号(查丢包/乱序)+ LCRC(查损坏)+ 重传缓冲(留后手);
2. **累计确认**:Ack 一次确认一串包,协议开销小;
3. **错误恢复对软件透明**:重传是硬件的职责,软件看到的永远是"可靠的链路";
4. **独立小包**:DLLP 只在相邻端口间流动,与数据通路(TLP)分离,互不干扰。

理解这套机制,对排查 PCIe 链路问题很有帮助——比如"链路偶尔 CRC 错误但数据没错"这类现象,本质就是 LCRC 校验在起作用、重传机制在悄悄兜底。下篇讲事务层:TLP 长什么样、posted/non-posted 事务、路由是怎么决策的。
